# Industrial Control Systems Database (SQL)

📌 **Описание проекта**

Данный репозиторий содержит практический проект по проектированию и оптимизации реляционных баз данных в рамках изучения информационных систем управления. Проект демонстрирует полный цикл разработки архитектуры данных: от инфологического проектирования (ER-диаграммы) до написания сложных аналитических SQL-запросов. В перспективе подобные архитектурные решения применяются для сбора, структурирования и хранения данных с производственных датчиков и оборудования.

🛠 **Стек технологий**

* **СУБД:** MySQL
* **Инструменты проектирования:** MySQL Workbench / DBeaver
* **Язык запросов:** SQL
* **Теория:** Нормализация баз данных (1NF, 2NF, 3NF), реляционная алгебра.

📂 **Структура репозитория**

* `/sql_scripts` — файлы с SQL-кодом, разбитые по темам.
* `/reports` — полные академические отчеты в формате PDF с теоретическим обоснованием.

🚀 **Выполненные задачи (Этапы)**

### Модуль 1: Проектирование и создание архитектуры БД (DDL/DML)
* Построение инфологической модели для предметной области «Институт».
* Проектирование и оптимизация ER-диаграммы (реализация связей `1:N`, `N:M`).
* Первичное наполнение таблиц тестовыми данными (`INSERT`).

### Модуль 2: Выборка данных, фильтрация и реляционные связи (JOIN)
* Выборка данных с использованием условий (`WHERE`, `LIKE`, `IN`, `IS NULL`).
* Работа с регулярными выражениями (`REGEXP`) для поиска по паттернам.
* Манипуляция со строковыми данными (`CONCAT`, `LEFT`).
* Объединение таблиц и построение связей (`INNER JOIN`).

### Модуль 3: Агрегация и аналитическая группировка
* Расчет метрик с использованием агрегатных функций (`COUNT`, `SUM`, `AVG`, `MAX`, `MIN`).
* Группировка данных (`GROUP BY`) и фильтрация агрегированных групп (`HAVING`).
* Применение `LEFT JOIN` для поиска записей без соответствий и контроля целостности данных.

### Модуль 4: Продвинутые вложенные запросы
* Работа со связанными (коррелированными) подзапросами.
* Использование операторов проверки наличия данных (`EXISTS` / `NOT EXISTS`).
* Применение кванторов общности (`> ALL`, `<= ALL`).

### Модуль 5: Сложные аналитические запросы и реляционные операторы
* Использование вложенных независимых подзапросов для сравнения с вычисляемыми значениями (средний балл, рейтинг).
* Комбинирование многотабличных объединений (`JOIN`) со сложными условиями фильтрации.
* Применение агрегатных функций с подсчетом уникальных значений (`COUNT(DISTINCT)`).
